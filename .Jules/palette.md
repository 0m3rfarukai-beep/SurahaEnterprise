## 2024-05-24 - Accessibility Labels for Visual Placeholder Forms
**Learning:** In the `GrowthCheckTool` (and similar components in this system), form inputs and selects often rely entirely on visual placeholders or surrounding UI context instead of explicit `<label>` elements. This creates a barrier for screen reader users who cannot associate the input with its purpose.
**Action:** When a `<label>` element is intentionally omitted for visual design reasons (like in a dense grid layout), always ensure an `aria-label` attribute is added directly to the `<input>` or `<select>` element to maintain WCAG compliance and accessibility. In addition, when dealing with inputs like URLs, apply specific types (e.g. `type="url"`) to help trigger the correct keyboard type for mobile users.
